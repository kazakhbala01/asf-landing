# Как вносить изменения в сайт ASF

Коротко: **в `main` напрямую не пушим**. Любая правка = отдельная ветка + Pull Request + ревью.

## Один раз при подключении

```bash
git clone https://github.com/kazakhbala01/asf-landing.git
cd asf-landing
npm install
npm run dev          # http://localhost:3000
```

Нужен Node.js 20 или новее. Технические детали проекта — в [HANDOFF.md](HANDOFF.md).

## Каждая правка

```bash
git checkout main
git pull                                  # забрать чужие изменения
git checkout -b fix/telefon-v-futere      # своя ветка под задачу
# ... правки ...
npm run build                             # обязательно: сборка должна пройти
git add -A
git commit -m "Исправлен телефон в футере"
git push -u origin fix/telefon-v-futere
```

Дальше GitHub предложит «Compare & pull request» — жмём, заполняем шаблон, создаём PR.

Названия ветвей: `fix/...` — исправление, `feat/...` — новый блок или страница, `content/...` — только тексты и фото.

## Что происходит после создания PR

1. Vercel собирает **превью-ссылку** — отдельный адрес только для этого PR. Там видно правку живьём, основной сайт при этом не меняется.
2. Владелец репозитория получает запрос на ревью автоматически (см. [.github/CODEOWNERS](.github/CODEOWNERS)).
3. После одобрения — **Squash and merge**. Через минуту-две изменения уезжают на astanasoapfactory.com.
4. Ветку после мёрджа удаляем (GitHub предложит кнопкой).

## Правила, чтобы не сломать сайт

- **Одна задача — один PR.** Не смешивать «поправил телефон» и «переделал каталог»: такой PR невозможно проверить.
- **`npm run build` перед пушем.** Vercel не задеплоит нерабочую сборку, но лучше узнать об ошибке локально.
- Цены, телефоны, адреса, статистика — только после сверки с клиентом.
- Товары, категории, контакты живут в одном файле: [lib/products.ts](lib/products.ts). Не дублировать их по компонентам.
- Фото — в `public/photos/`, JPEG, ширина до 1600px. Не заливать оригиналы с телефона по 8 МБ.
- Не коммитить `.env*`, `node_modules/`, `.next/`.

## Если нет прав на пуш

Значит вы не в списке участников. Тогда: кнопка **Fork** на странице репозитория → правки у себя в форке → **Contribute → Open pull request**. Права на пуш выдаёт владелец в Settings → Collaborators.

## Частые грабли

| Симптом | Причина и что делать |
|---|---|
| `Cannot find module './71.js'` | Запущен `npm run build` при живом `npm run dev` (общая папка `.next`). Остановить сервер, `rm -rf .next`, запустить заново. |
| Заменил(а) фото, а на сайте старое | Next кеширует оптимизированные картинки. `rm -rf .next` и перезапуск. |
| `! [rejected] ... non-fast-forward` при пуше | Кто-то запушил раньше. `git pull --rebase`, разрулить конфликты, пушить снова. |
| Конфликт в `lib/products.ts` | Два человека правили каталог. Открыть файл, оставить оба изменения вручную — не выбирать «ours/theirs» наугад. |
